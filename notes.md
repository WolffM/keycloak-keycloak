## Steps to reproduce
1. From the repository root, run `mvn -pl common -Dtest=ProfileTest test -DskipITs` to confirm baseline behavior.
2. Add an assertion in `ProfileTest.beforeClass` expecting `Profile.Feature.DYNAMIC_SCOPES` to be `Type.PREVIEW`.
3. Run `mvn -pl common -Dtest=ProfileTest test -DskipITs` again.
4. Observe the test failure output generated by Surefire for the `beforeClass` assertion.

## Observed
The test failed with `AssertionFailedError: expected: <PREVIEW> but was: <EXPERIMENTAL>` in `org.keycloak.common.ProfileTest.beforeClass(ProfileTest.java:48)`. This shows the dynamic client scopes feature is still classified as experimental. Because of that classification, it does not align with the requested promotion status and behaves as an experimental feature in profile metadata.

## Expected
`Profile.Feature.DYNAMIC_SCOPES` should be classified as `Type.PREVIEW`, so profile metadata reflects official preview support for parameterizable scopes. The corresponding profile test should pass with this expectation, and the feature should appear among preview features rather than experimental ones. This matches the issue goal to promote dynamic client scopes from experimental status.
